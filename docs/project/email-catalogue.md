# Email catalogue

Generated by `php artisan nawy:emails:catalogue` from `app/Shared/Notifications/Email/Catalogue/*` — edit the code, then regenerate. Texts are the built-in defaults; admins override them per country and language in Admin → Content → Notification templates (preview, test send, reset, version history).

**Engine:** every event goes through `Emails::send()` / `Emails::alertAdmins()` → one queued `EventEmail` per recipient on the `mail` queue (5 tries, back-off) → channels `mail` (+ `bell` in-app/push, `sms` where listed) → branded EN/AR layout (RTL for Arabic) with a plain-text part, in the recipient's language → `email_log` row (queued → sent / failed / suppressed / skipped / bounced / complained). Idempotent per event + entity + recipient. See `docs/deploy/email.md` for providers, DNS and webhooks.

**Categories:** `transactional` (always sent) · `security` (always sent) · `reminders` (on by default, can be turned off, one-click unsubscribe) · `opportunities` (on by default, can be turned off, one-click unsubscribe) · `recommendations` (on by default, can be turned off, one-click unsubscribe) · `cart_reminders` (opt-in, one-click unsubscribe) · `admin_alerts` (opt-in, one-click unsubscribe). Admin alerts are opted in per alert and only offered for alerts whose permission the admin holds.

## Scheduled reminders

`nawy:emails:reminders {kind}` (routes/console.php): `seller-sla` hourly (seller.sla_unconfirmed / seller.sla_not_shipped), `abandoned-carts` hourly (cart.abandoned, opted-in customers only), `document-expiry` daily (document.expiring at 30 and 7 days), `renewal-reminders` daily (membership.renewal_upcoming, subscription.renewal_upcoming), `credit-expiry` daily (wallet.credit_expiring), `review-requests` daily (review.request), `promotion-expiry` daily (travel.promotion_expiring). Ad expiring runs in `nawy:classifieds:expire`, FBN inbound in `nawy:fbn:inbound-reminders`. All respect preferences and are idempotent per entity + window.
